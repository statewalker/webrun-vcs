**`commit -i`, `COMMIT_EDITMSG` for every commit, `:(attr:...)` pathspecs and git's exit codes on errors.**

- `CommitCommand.setInclude(...paths)` is git's `commit -i` / `--include`: the tracked paths named are staged into the held index lock as `add_files_to_cache` stages them, then the whole index is committed. It is refused with `--only` paths, with `-a` and without paths, in git's words; an element that matches no index entry fails as git 2.5x fails ("did not match any file(s) known to git"). `setAll` with paths now fails with git's "paths '<path> ...' with -a does not make sense".
- Every commit writes `COMMIT_EDITMSG` as git's `prepare_to_commit` writes it: a `-m` message (or `--amend --no-edit`'s, or a prepared `MERGE_MSG` under `setEdit(false)`) with its whitespace cleaned up unless verbatim, before a commit with nothing to commit is refused. The refusals come in git's order (nothing to commit, then an empty message, then an untouched template), `-v` cuts a `-m` message at the scissors line, and `setEdit(false)` keeps a prepared message's comments (whitespace cleanup, as `--no-edit`). A prepared `MERGE_MSG` without an editor is taken as `git commit --no-status` takes it once the editor accepts it. `cherry-pick` / `revert --continue` write `COMMIT_EDITMSG` as their `git commit --no-edit --cleanup=strip` does, and `merge --continue` concludes the merge through `git commit` (its template, the status included).
- `:(attr:<spec>)` pathspec magic (`name`, `-name`, `!name`, `name=value`, several per element) matches paths by their attributes from `.gitattributes`, `info/attributes`, `core.attributesFile` and the index, in status (tracked paths and the untracked scan, which matches an untracked directory by its own name), add, rm, commit `--only` / `-i`, diff, clean, stash push and combined `log` diffs. Status no longer refuses it; a command that does not take it refuses with git's "pathspec magic not supported by this command: 'attr'". `ContentAttributesContext.isDirectory` reads a directory's attributes as git's `git_check_attr` of a name ending in `/`; an untracked-scan pathspec may answer with a promise.
- A `diff.submodule` without a value fails status, commit, log and merge as git 2.5x's `git_diff_ui_config` fails them.
- `GitApiError.exitCode` is the exit status native git ends with: given, else from the message's lines (`usage:` 129, `fatal:` 128, a leading `error:` 1), else the class's default (1 for `NoMessageError`, `EmptyCommitError`, `AddFailedError`, `RmFailedError`, `MvFailedError`, `SwitchRefusedError`, `PathNotInIndexError`, `PathNotFoundInTreeError`, `MergeConflictError`, `InvalidMergeHeadsError`, `NotMergedError`, `CannotDeleteCurrentBranchError`, `StashApplyFailedError`, `PushRejectedException`; 129 for `MissingArgumentError`; 2 for `RemoteNotFoundError`, 3 for `RemoteAlreadyExistsError`; 128 otherwise); `withExitCode` sets it where the condition decides.
