**`stash push -- <pathspec>` fails as git does after saving; `DA` for intent-to-add over HEAD; unreadable-directory and sparse-checkout messages; skip-worktree entries present in the worktree and the sparse-checkout patterns.**

- **vcs-commands:** `stash push -- <pathspec>` reproduces git's failures after the stash is saved (`StashPathspecResetError`, carrying `stashCommit`): `git apply --index -R` refusing a path HEAD has, the index does not and the worktree holds untracked ("error: b.txt: already exists in working directory", the index updated by git's `add -u`, the worktree untouched); with `-u`/`-a`, git's `git add -- <pathspec>` dying on an element that matches nothing or naming ignored files (the others added); with `--keep-index`, `git checkout` naming an element the index tree lacks (the paths reset, the index tree not checked out); git's `git apply` of an empty patch, when the add brings the named paths back to HEAD (`git rm --cached c.txt; git stash push -u -k -- '*.txt'`: "error: No valid patches in input (allow with "--allow-empty")", c.txt re-added and kept, no `--keep-index` checkout). Pathspec errors name the elements as git hands them on: `:(prefix:0)x` (git 2.5x) or `:(,prefix:0)x` (`setCompatibility("2.43")`), also in the "did not match any file(s) known to git" check; `prefixOriginElement` spells them.
- **vcs-commands:** status shows an intent-to-add entry over a path of HEAD as git does: `DA` (`DD` once the file is gone), with HEAD's side in porcelain v2, `removed` listing it, and a rename from it keeping only its worktree side.
- **vcs-commands:** status, add and clean report git's "warning: could not open directory 'u/': Permission denied" for directories the scan cannot list (`Status.warnings`, `AddResult.warnings`, the new `CleanResult.warnings`); a real clean removes an empty unreadable directory (rmdir) and warns "failed to remove u: <reason>" for the others, the reason rmdir's ("Directory not empty", "Permission denied", ...).
- **vcs-commands:** `add` (also `--chmod`, `--refresh`, `-u`, `--dry-run`) advises as git does on pathspec elements that match only skip-worktree entries ("The following paths and/or pathspecs matched paths that exist outside of your sparse-checkout definition…", hint off with `advice.updateSparsePath=false`), writes the index and rejects with `AddFailedError` (git's exit status 1). `AddCommand.setCompatibility("2.43")` words the advice's last hint as 2.43 does ("git config advice.<name> false"). With `core.sparseCheckout`, add asks the sparse-checkout patterns too (git's `path_in_sparse_checkout`, cone and non-cone): tracked paths outside them are not updated, untracked files outside them are advised on instead of added; the index is written only when the add changed it (git's `SKIP_IF_UNCHANGED`).
- **vcs-commands:** in a sparse checkout, every index-reading command (those that re-read the index at their start, and status) clears the skip-worktree flag of entries whose files are present in the worktree, as git's `clear_skip_worktree_from_present_files` (unless `sparse.expectFilesOutsideOfPatterns`): `add --refresh d/b` of a recreated `d/b` refreshes it and exits 0.
- **vcs-working-tree:** `clearSkipWorktreeFromPresentFiles` (one stat per missing directory, as git's `path_found`), `parseSparseCheckoutPatterns` (`path_in_sparse_checkout`), the optional `Staging.clearSkipWorktree` (flags cleared as part of the read: not an edit, written by the next `write()` or `refreshStats()`); an index editor finished without edits changes nothing. `WorktreeWalkOptions.onUnreadable` receives the listing's error; `findUntrackedFiles` takes `onUnreadable`; `unreadableDirectoryWarning` words git's warning.
- **vcs-store-files:** `FileWorktree.getEntries` without `lstatMany` keeps at most 48 `getEntry` calls in flight (slow asynchronous FilesApis); and stops taking paths once one fails; the staging editor's in-place merge falls back to the full sort when a path's stages are out of order (a malformed index). `GitLinkedWorktrees.pathState` takes a directory it cannot list as not empty (git's `is_empty_dir`), and `deleteAdminRootIfEmpty` ignores a failed removal (git's `delete_worktrees_dir_if_empty`).
- **vcs-utils-node:** `list()` of a directory that cannot be read (EACCES) now throws, as `listKinds` does, instead of listing nothing; a missing directory still lists nothing.
- **vcs-utils:** the `FilesApi.list` contract documents that an unreadable directory fails the listing.
