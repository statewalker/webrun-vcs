**`git.fsck()` and `git.verifyPack()` read each pack once, and SHA-1 is two to three times as fast.**

On a repacked 5000-commit repository (39.7k objects in one pack), over the built packages, a full `fsck` takes 1.0 s instead of 2.3 s, `--connectivity-only` 0.6 s instead of 0.9 s, and `verify-pack -s` 0.7 s instead of 1.7 s. Output, exit status and verdicts are unchanged; the native comparison tests pass on git 2.43 and 2.56.

- **vcs-commands (fsck, verify-pack):** a pack is checked in one sequential read: each entry's bytes feed the pack's SHA-1 and the entry's CRC-32 and are inflated there, once; a delta is applied to its base from a 16 MiB cache of the objects unpacked just before it (in pack order a base precedes its deltas), and each object is hashed in one call. Whatever that path does not handle as it stands (REF_DELTA, a base not cached, an object over 1 MiB, an entry reached through a corrupt part of the idx, any failure) goes through the pack's own reader, so error messages and verdicts are those of before. The pack checksum errors are still printed before the entries' output. The ids are read straight from the idx and the object table is probed with their bytes, the commit parser hands back where its ids are instead of decoding them, and the object hash keeps each slot's key next to its object number. A tree checked in full is remembered as the object numbers of its entries, so the connectivity walk does not unpack it again (not with `--name-objects`, nor for an object with a copy that failed a check); the walk reads through the store's synchronous path (`getNow`) and runs without awaiting when nothing needs I/O. `--connectivity-only` inflates no blob: a dangling object's type comes from its pack entry's header, following delta bases, as git's `packed_object_info`. `verify-pack` takes each entry's header from the same read instead of reading it again.
- **vcs-commands (`fsck-object-checks`):** new `scanTree` (a tree's entries as a table, without an object per entry), `parseCommitLinks` (`parseCommitBuffer` with the ids left in place), `hexIdAt` and `rawIdAt`; `fsckTree` takes a tree's `scanTree` table when the caller has one.
- **vcs-utils:** SHA-1 is this package's own instead of `@noble/hashes`': a fully unrolled JavaScript block function, and a WebAssembly one assembled at load time (no binary shipped) wherever the runtime compiles WebAssembly from bytes; elsewhere (workerd, a CSP without `wasm-unsafe-eval`) the JavaScript one runs. `createSha1()` uses it, so every caller gets the speed. New exports: `Sha1` (the incremental hasher without the `Hasher` wrapper), `sha1Of(head, body)` (a header and a body hashed as one message in a single WebAssembly run, padding included) and `sha1Wasm()`. CRC-32 is computed slicing by 8 (eight bytes per step, about twice as fast).
