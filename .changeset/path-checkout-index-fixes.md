Path checkouts and resets write the index git writes. `reset -N` (with or without paths) and `apply -N` store the empty blob their intent-to-add entries name, so native `git status` and `git write-tree` read the result. A stage-0 entry that `reset <tree-ish> -- <paths>`, `checkout <tree-ish> -- <paths>` or `restore --source` adds replaces only the stage-0 entries it clashes with as a file or a directory (git's `has_file_name`/`has_dir_name`): conflict stages stay, so `restore` then refuses the unmerged path as git does. No-overlay removals prune the emptied directories of a file already gone (never beneath a symbolic link) and warn where git's `unlink`/`rmdir` fails ("unable to rmdir 'sm': Directory not empty", "unable to unlink 'p': Is a directory"). `checkout -m`/`--conflict` and `restore -m` merge with the `merge` attribute's driver (union, binary, `-merge`, registered drivers) and `conflict-marker-size`, through the same `ll_merge` as the merges. A blob missing partway through a path checkout is reported for its path ("unable to read sha1 file of ..."), the other paths are still checked out and the index written, and the result carries git's exit status 255 (`CheckoutResult.exitCode`).
