**Several refs deleted in one transaction, the ref lock timeouts from the config, `cherry-pick -e` / `revert -e`, and the root refs in the reference-transaction hook.**

- New optional `Refs.removeAll(names, { legacy, message })` (`RefRemoveAllOptions`), git's `delete_refs`: `FileRefStore.removeAll` deletes all the refs in one transaction as git 2.5x does (none deleted when one cannot be), or with `legacy` as git 2.43's files backend (the refs dropped from `packed-refs` in a transaction of the packed store first, `packed-refs` rewritten even when absent, then each ref in a transaction of its own, going on past a failure). `branch -d/-D`, `tag -d`, `remote remove` and `fetch --prune` use it (legacy when the hook runner follows 2.43); `branch -d` and `tag -d` check every name first and still delete the others when one is refused, reporting that one afterwards, as git does. The reflog of a deleted ref always goes with it.
- The files ref store locks a batch's refs in the batch's order (git's), and a lock it cannot take tells the hook `aborted` for the packed store's transaction of the deletions locked so far. A batch of deletions only is committed as git commits it (packed-refs rewritten only when it names one of them, then the loose files removed). A batch without deletions no longer needs `packed-refs.lock`: when another writer holds it, the batch commits its loose refs as git does instead of failing.
- `createGitFilesBackend` reads `core.packedRefsTimeout` (default 1000 ms) and `core.filesRefLockTimeout` (default 100 ms) from the repository's config when the options are not given; a negative timeout waits forever, 0 tries once.
- `CherryPickCommand.setEdit` / `RevertCommand.setEdit` (`-e`, `--no-edit`) with `setEditor`: each pick that applies cleanly is committed by `git commit -n -e`, as git's sequencer runs it: the message in git commit's template through the editor, `prepare-commit-msg` told `merge`, `post-commit`, no `pre-commit` or `commit-msg`, `GIT_REFLOG_ACTION` set for the hooks. `GitCommand.shareHooksOf(source, env)` takes the variables such a child run exports.
- The files store tells its reference-transaction hook about the root refs git updates in transactions (`isRootRefName`: `ORIG_HEAD`, `CHERRY_PICK_HEAD`, `REVERT_HEAD`, `REBASE_HEAD`, ...; `AUTO_MERGE` for git 2.5x only), written with `set` (or a one-command `batch` with an old value) and deleted with `remove`. Commands delete them as git does: a commit, a reset and a branch switch delete `AUTO_MERGE` whether it exists or not, a cherry-pick's commit `CHERRY_PICK_HEAD`; a reset (and a sequencer's `--abort` / `--skip`) writes `ORIG_HEAD` given the value it read and moves HEAD expecting the commit it left; the sequencer's commits move HEAD in one transaction expecting its parent; merge's hooks all see its `GIT_REFLOG_ACTION`.
