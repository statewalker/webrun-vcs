**Merge, cherry-pick, revert, rebase and pull write the working tree as git does.**

- **vcs-commands:** `merge` is git's merge-ort (renames, line merge, modify/delete, rename/delete, rename/rename, binary, distinct types, file/directory placement as `file~HEAD`) written to the index and the worktree through a two-way switch from HEAD, smudged with the attributes of the resulting index. Before anything is written it refuses as git: local changes, staged changes (`  a b` / `Merge with strategy ort failed.`), untracked files in the way, unmerged entries, a merge or cherry-pick in progress. Conflicts leave git's markers (`merge.conflictStyle` `merge`, `diff3`, `zdiff3`; labels `HEAD`, the branch, `<abbrev> (<subject>)`, `parent of ...`), stages 1-3 and git's state (`MERGE_HEAD`, `MERGE_MSG`, `MERGE_MODE`, `ORIG_HEAD`, `AUTO_MERGE`, `SQUASH_MSG`, `CHERRY_PICK_HEAD`, `REVERT_HEAD`, `sequencer/`, `rebase-merge/`, `REBASE_HEAD`), so native git continues or aborts what we started and the other way round. New: `MergeCommand.setOperation(MergeOperation.ABORT | CONTINUE)`, `setAuthor`, `setCommitter`, `setAutoStash` (`merge.autoStash`); `CherryPickCommand` / `RevertCommand.setOperation(SequencerOperation.CONTINUE | SKIP | ABORT | QUIT)`, `setCommitter`, several commits through `sequencer/`; `RebaseCommand` keeps git's `rebase-merge/` state (continue, skip, abort across implementations), `setCommitter`, `setAutoStash` (`rebase.autoStash`), refuses on unstaged or staged changes, drops picks that become empty; `PullCommand.setRebase(true)` rebases (`PullResult.rebaseResult`) and a merging pull uses git's message (`Merge branch 'x' of <url>`). Results carry `output` (merge-ort's `Auto-merging` / `CONFLICT` lines) and `message` (git's error); a refused merge is `FAILED` with `failingPaths`. A content merge of files both sides changed no longer conflicts when the edits do not touch. `stash apply` shares the merge (and its conflict refinement) and records `AUTO_MERGE`.
- **vcs-commands (what they never lose):** `merge --abort`, `cherry-pick` / `revert --abort` and `--skip` (git's `reset --merge`), and `rebase --abort` / `--skip` and the autostash (`reset --hard` as `reset_head` runs it) refuse as unpack-trees does instead of deleting untracked work: an untracked file where a file goes or on a leading path of one (`Untracked working tree file 'd' would be overwritten by merge.`), an untracked file or a nested repository in a directory a file replaces (`Updating 'd' would lose untracked files in it`), a file with unstaged changes (`Entry 'x' not uptodate. Cannot merge.`); `reset --hard` writes back tracked files deleted from the worktree. Merges, fast-forwards, picks and rebases see nested repositories in a directory a file replaces (`would lose untracked files in them`). A pick a rebase cannot write is rescheduled as git does (`It has been rescheduled`), `--continue` applies it. `merge --autostash` refuses unrelated histories before stashing, and applies the autostash back on any later failure; an autostash with a checkout that keeps no state files is refused rather than stranded. A deleted tracked file is an unstaged change for `rebase` (`--autostash` stashes it). `merge --abort` refused by the reset keeps `MERGE_AUTOSTASH` on `refs/stash`.
- **vcs-commands (results as git's):** a rebase picks in git's order (`rev-list --reverse --topo-order`, merges dropped) and keeps `msgnum` / `end` as git counts them; `cherry-pick -n` / `revert -n` of several commits merge into the index (`revert -n` records `REVERT_HEAD`, a revert of an empty commit does not); a rename onto a path the other side added is merge-ort's rename/add (an add/add at the new path); `stash apply` labels the diff3 base `Stash base`, records no `AUTO_MERGE` when the stash is "Already up to date.", applies `--index` as `git apply --cached` (`does not exist in index`, `patch does not apply`, `ORIG_HEAD`), restores untracked files after the tracked changes (a refused or partial restore as `checkout-index --all`: `already exists, no checkout`); a refused merge's `restore_state` removes the directories it leaves empty. `add` resolves a conflict (stages 1-3 replaced by stage 0, or removed for a deleted file) and records git's resolve-undo (`REUC`); `commit` finishes a merge (`MERGE_HEAD` parents, reduced unless `MERGE_MODE` is `no-ff`, `MERGE_MSG` / `SQUASH_MSG` as the default message, no empty-commit refusal), a cherry-pick (the picked commit's author) or a revert, removes their state files (and the sequencer's after the last pick), applies `MERGE_AUTOSTASH`, refuses unmerged files as git (`Committing is not possible because you have unmerged files.`). Picks in rebase, cherry-pick and revert read each tree once, store only the directories a pick changes, plan and write only the changed paths, and merge the changed index entries into the index instead of sorting it whole; abbreviated todo ids resolve through one pass over the object store.
- **vcs-utils:** `mergeLines` is git's `xdl_merge`: zealous conflict refinement (shared lines leave a conflict, conflicts at most three lines apart join), `style` (`merge`, `diff3`, `zdiff3`) with `baseLabel`, `favor` (`ours`, `theirs`, `union`), `markerSize`, and git's choice of CRLF markers.
- **vcs-working-tree:** `Checkout` gains optional operation state files (`readStateFile`, `writeStateFile`, `removeStateFile`, `listStateDir`); `MemoryCheckout` keeps them in memory. `Staging.recordResolveUndo` (optional) and `IndexFile.recordResolveUndo` write resolve-undo records (`REUC`). `WorktreeWriteOptions.discardUntracked`: with `replaceInTheWay`, a directory in the way is removed whatever it holds (`reset --hard`, `checkout -f`); without it only one holding nothing but ignored files and empty directories.
- **vcs-store-files:** `GitCheckout` reads and writes them in the git directory (`GitCheckoutFilesApi.list` lists a state directory). `FileWorktree` refuses (throws) to replace a directory holding an untracked file or a nested repository unless `discardUntracked`; the `FileStagingStore` editor applies edits path by path (a removal takes every stage of a path, an update replaces its stage-0 entry).
