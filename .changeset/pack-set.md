**New: `openPackSet(files, packDir, options?)`**, reading installed packs as git's object database does. Every `pack-<id>.idx` is validated on open (version 2 or 1, fan-out, length, its own SHA-1, sort order, the 64-bit table, and the pack trailer it names); a corrupt pack is skipped and listed in `skipped`, and opened again only if its files change size or mtime (an idx seen half-written). Lookups use the fan-out table and a binary search; whole objects stream from the inflater; deltas resolve through one byte-bounded base cache for the set (checkpoints along each chain), and callers always get copies. A miss, and every `list()` or `packs()` call, rescans the directory at most once per `rescanIntervalMs` (default 1 s), so packs written by native git after open are found; `refresh()` rescans now. `get` reads the first chunk before returning, so a copy broken from its start fails there and the next copy is tried; a copy found corrupt is marked bad and counts as absent for `has` and `freshen(id)` (the check before skipping a write, which also drops a pack whose file is gone; a pack seen within the rescan interval is trusted). Returning the content without reading it closes the pack read. REF_DELTA bases in other packs, or outside the set through `externalBase`, are resolved with cycle detection (`PackError`). `entry(id)` returns an entry as stored (kind, size, base id, CRC-32 and its compressed bytes; `raw()` checks the CRC before it yields a byte, reading the entry twice) for pack reuse. `install()` delegates to `installPack` and adds the pack; `remove()` deletes `.idx` first, then `.pack`, `.keep`, `.rev`. Also new: `openPack(files, packPath, idxPath, options?)` for one pack, `DeltaBaseCache`, and the types `Pack`, `PackSet`, `PackFile`, `PackedEntry`, `OpenPackOptions`, `OpenPackSetOptions`.

**Changed in vcs-store-files:** `withPacks(loose, packs)` and `skipPacked(store, packs)` take a `PackSet` instead of a `PackDirectory`. Reads go to the packs first, then loose objects; a packed copy failing before `get` returns gives way to a loose copy, one failing later is marked bad so the next read goes loose. Pack misses rescan at most once per second. Packed objects stream instead of being buffered, and `getRaw` is built from `get`. Writes skip an object only if a pack still on storage holds a sound copy of it. `PackDirectory` takes an `onChange` callback (its failures are ignored), which the backend uses to refresh `packs` after `addPack` and `removePack`. `createGitFilesBackend` returns the set as `packs` (and still `packDirectory`, for repack and gc).
