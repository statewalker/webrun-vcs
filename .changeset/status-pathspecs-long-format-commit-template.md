**`git status` takes full pathspecs and prints every text format; `git commit` gets `--dry-run` and git's editor template.**

- `StatusCommand.addPath` takes pathspec elements as `git status -- <pathspec>` does (pathspec.c): wildcards (`fnmatch` without `WM_PATHNAME`), `:(glob)`, `:(literal)`, `:(icase)`, `:(exclude)` / `:!` / `:^` (an implicit `.` when every element excludes), `:/` and `:(prefix:N)`, and the `GIT_LITERAL_PATHSPECS`, `GIT_GLOB_PATHSPECS`, `GIT_NOGLOB_PATHSPECS` and `GIT_ICASE_PATHSPECS` variables of the host environment (new `GitHostEnvironment.pathspecs`). Tracked paths match as `ce_path_match` matches them (a gitlink as a directory); a path below a submodule no longer selects the submodule. `:(attr:...)` is refused with git's "pathspec magic not supported by this command". Bad elements fail with git's messages (`InvalidArgumentError`).
- `scanUntracked` accepts any pathspec through the new `matcher` option (`UntrackedScanPathspec`): dir.c's `common_prefix_len`, `treat_leading_path`, `simplify_away` and `match_pathspec_item` with its wildcard and leading-pathspec branches. The untracked cache stays unused whenever a pathspec is given.
- `StatusCommand.callText()` prints the status as `git status` does: the long format (branch line, tracking report with `status.compareBranches`, merge / am / rebase / interactive rebase / cherry-pick / revert / bisect / sparse checkout lines, section headers, `advice.statusHints`, `status.displayCommentPrefix`, the closing line, `--show-stash`, `-v` / `-vv`), `short`, `porcelain` and `porcelain-v2`, with `--branch` and `-z`, and the deferred `status.short`, `status.branch`, `status.aheadBehind` and `status.showStash`. `formatStatusPorcelain` takes `z`. New `setReferenceCommit` and `setWriteIndex`.
- `CommitCommand.callDryRun()` is `git commit --dry-run` (and `--short`, `--porcelain`, `--long`, `-z`, `--branch`, `-u<mode>`, `-v`) with `-a`, paths and `--amend`, returning git's exit code (1 when nothing is committable).
- `CommitCommand.setEditor()` runs an editor over git's commit template written to `COMMIT_EDITMSG`: the message so far, the commented help for the cleanup mode, the merge / cherry-pick notice, `Author:` / `Date:` / `Committer:` lines, the commented status (`commit.status`, `--no-status`) and with `-v` the diff below the scissors line, with `core.commentChar` / `core.commentString` (`auto` too). The edited message is cleaned up as git cleans it (`default` strips comments, `scissors` cuts at the scissors line). New `setEdit`, `setIncludeStatus`, `setVerbose`, `setUntrackedFiles`, `setStatusFormat`, `setShowBranch`, `setNullTermination` and `setAheadBehind`.
