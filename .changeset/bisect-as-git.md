**`git bisect` as git 2.5x runs it.** New commands on the `Git` facade: `bisect()` (git's arguments as given), `bisectStart()`, `bisectState(term)`, `bisectSkip()`, `bisectNext()`, `bisectReset()`, `bisectTerms()`, `bisectLog()`, `bisectReplay()` (over a log's text) and `bisectRun()` (the command run through a host hook: 0 good, 125 skip, 1-127 bad, 128 or more aborts; 126/127 verified on a good commit). They port `builtin/bisect.c` and `bisect.c`: `find_bisection` (weights, the halfway shortcut, `--first-parent`), skipped commits with git's pseudo-random `skip_away`, the merge-base checks, path-limited bisection, custom terms, `--no-checkout` (BISECT_HEAD), `--reset-when-found`, the state files and `refs/bisect/*` byte for byte, the candidate checked out with git's reflog line, stdout ("Bisecting: N revisions left to test after this (roughly M steps)", the first bad commit with `git show --stat --summary`), git's errors and exit codes. Each result carries `stdout`, `stderr`, `exitCode`, the candidate and the first bad commit. The checkouts print what `git checkout` prints, shallow clones bisect as git bisects them, a path-limited bisection compares trees pruned (subtrees that are equal or outside the pathspec are not read), and stdout keeps the raw bytes of subjects (`stdoutBytes`).

**`git log --summary`.** `LogCommand.callBytes`/`callText` take `summary` (`create mode`, `delete mode`, `rename ... (n%)`, `copy`, `mode change` lines, as diff.c's `diff_summary`), and `DiffCommand` prints the `summary` format; a shallow commit is shown without parents.
