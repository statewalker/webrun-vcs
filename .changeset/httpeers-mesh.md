**New package: git and Git LFS over an httpeers mesh.** `meshGitHandler` puts the smart-HTTP server of `@statewalker/vcs-transport` behind `@statewalker/httpeers-access` (Biscuit membership tokens bound to the transport-proven peer, capabilities from mesh roles through `gitRules`, revocation): upload-pack needs `git:read`, receive-pack `git:write`, or `git:write-own`, which limits a push to `refs/peers/<peerId>/*` (refused refs answered `ng … not allowed`, checked before the pack is read). `meshLfsHandler` does the same for `serveLfs` (lock owners are peer ids) and negotiates a `ranged` download transfer when a client offers it, while native git-lfs keeps `basic`. `lfsSwarmDownload` fetches byte ranges of one object from several peers at once, writes them in order within a bounded window, verifies SHA-256 and size at the end, falls back between sources, resumes from a store's partial and reports peers that served wrong bytes. `servePeerConnection`, `peerFetch`, `meshGitFetch` and `meshGitPush` run the existing clients over a webrun `Duplex`.
