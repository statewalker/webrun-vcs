`--recurse-submodules` for clone, fetch, pull and push (statewalker/statewalker-root#332). `FetchCommand.setRecurseSubmodules` (yes, on-demand, no) and the configuration (`fetch.recurseSubmodules`, `submodule.recurse`, `.gitmodules`' `fetch.recurseSubmodules`, `submodule.<name>.fetchRecurseSubmodules`) recurse as submodule.c's `fetch_submodules`: on demand by default, the changed submodules found by walking the fetched history (also those not in the index, `at commit <id>`), a second fetch of recorded commits still missing, git's lines in `FetchResult.submoduleOutput`, the results in `FetchResult.submodules`, failures in `submodulesFailed`; submodules are fetched one at a time (`submodule.fetchJobs` only parallelises). `CloneCommand.setRecurseSubmodules` (pathspecs), `setShallowSubmodules`, `setAlsoFilterSubmodules` (`clone.filterSubmodules`) and `setRemoteSubmodules` write `submodule.active` and run `submodule update --require-init --recursive` after the checkout (`CloneResult.submodules`); `SubmoduleUpdateCommand` gains `setFilter` and `setSingleBranch`. `PullCommand.setRecurseSubmodules` and `submodule.recurse` pass the mode to the fetch and update the submodules after the merge or rebase (`PullResult.submodules`), refusing a rebase over locally recorded submodule changes. `PushCommand.setRecurseSubmodules` (check, on-demand, only, no) and `push.recurseSubmodules` check or push the submodules first (`submodule--helper push-check` included, `PushResult.submoduleOutput`). Submodule fetches, clones and pushes reach the submodules' URLs through guarded transports: credentials go only to the superproject remote's origin. A submodule's FETCH_HEAD is now written to its git directory (vcs-store-files `openGitlink`), and a fetch from a local path naming no repository leaves FETCH_HEAD empty, as git does.
