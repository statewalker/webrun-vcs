**Renames merge as git's merge-ort with directory renames; a rebase pick costs about half as much; `core.ignorecase` follows the filesystem.**

The merge redoes itself once the renames are known when reading the trees it deferred would triple the paths it reads (merge-ort's `redo_after_renames`, with its cached renames, targets and irrelevant sources), keeps a directory a known rename goes into out of the trivial directory merges, and leaves a rename that a directory rename moves back onto its source where it is. A differential fuzz of rename/rename (1to2, 2to1), rename/add and rename/delete mixed with directory renames, under `merge.directoryRenames` `true` and `conflict`, now matches `git merge-tree --write-tree --messages` (tree, conflicted stages and messages) on git 2.43 and 2.56.

A rebase or cherry-pick pick touches fewer files: reflogs, `rebase-merge/done` and `rewritten-list` are appended to (`O_APPEND`) instead of rewritten, a ref update reads each loose ref once per look (the plan, then under the locks), the index is written as one buffer created in its lock (its checksum by Web Crypto) and rewritten without copying the entries it keeps, loose objects are written with an exclusive create and one rename, and the small state files git writes with `write_file` (`msgnum`, `end`, `head-name`, ...) are written in place. The todo lists, messages and `author-script` (`git-rebase-todo`, `sequencer/todo`, `message`, `MERGE_MSG`, `SQUASH_MSG`, ...) are still written to a temporary renamed into place, as git's lock files, so a crash never leaves them missing or partial; a pick writes `git-rebase-todo` before it appends to `done`, as git's `save_todo`, and a rebase whose todo is gone fails (`RebaseTodoMissingError`) instead of finishing with commits dropped. A loose object whose exclusive create read the content and still failed is refused instead of written empty, and `PosixNodeFilesApi`'s directory creation reports a directory removed while it is made as missing (`ENOENT`). `FilesApi` gains an optional `append` (implemented by the Node, in-memory, mounted and simulated-link FilesApis; `appendByRewrite` for the others), `Checkout` an optional `appendStateFile`, and `encodeIndexFileBytes` writes an index at once. `PosixNodeFilesApi` checks paths with synchronous `lstat`s, as git does: the async round trip cost some 25 times the call.

With `core.ignorecase`, a restore (checkout, reset, merge, stash, clone) refuses or reports case variants only where the worktree folds case (`restoreCaseOptions`, from the worktree's new `foldsCase`, which looks without writing); on a filesystem that keeps case a file beside a directory of another case checks out as native git checks it out, and an untracked file in another case of a path the switch replaces is refused as in the way unless it is that path's own file (its stat matches the index entry, as git's `icase_exists`). `foldsCase` looks at the worktree's own entries, and at the git directory only when it lies inside the worktree.
