**Faster small-object reads: zlib's table builder in `inflateWhole`, and no promise per layer for objects in memory.**

On a repacked 5000-commit repository (Node, files backend, backend already open) a rev-walk that parses every commit takes about two thirds of the time it took, and reading 2000 blobs about 85% (packed or loose). Results, errors and the streaming of large objects are unchanged.

- **vcs-utils:** `inflateWhole` builds its Huffman tables as zlib's `inflate_table` does (a 9-bit root table, 6 bits for distances, and sub-tables for longer codes, in typed arrays allocated once), and the code sets come straight from the reader of the block header, which lists the symbols with a code as it decodes their lengths (no scan of the 286 symbols per table). Long codes no longer go bit by bit. The fast loop runs whenever 8 input bytes are left, with the output bound checked per symbol, so objects decoded into a buffer of their exact size take it too; the bit buffer stays a 31-bit integer. Adler-32 sums four bytes at a time. A commit inflates in about 60% of the time, a 5 KB blob in about 70%. A dynamic block whose code length code has no codes now fails as zlib does (`TruncatedStreamError` when the input ends, as zlib reads each bit as a length of 0) instead of with `InflateError`, and a stream whose distance code is invalid near the end of the input now reports `invalid distance code` (as zlib does) instead of `TruncatedStreamError`: the differences from before found by differential fuzzing against zlib (700 000 streams), all toward zlib. A dynamic table cache keyed by the code lengths was measured and left out: under 1% of a repository's commit blocks, none of its tree blocks and 4% of its blob blocks repeat a header.
- **vcs-core:** `runSteps` runs a read written as a generator that yields only the promises it must wait for: synchronously to its end when it yields none. `PackFile.getNow` and `PackSet.getNow` (optional on the interface) return the object without a promise when its entries are in loaded windows or the delta base cache, and a promise otherwise; `get` keeps its contract. A pack remembers its last id lookup, so the set's `has` then `get` parses and searches the idx once. The commit store decodes an object it gets in memory without another async call, and `commitFromBytes` and `parsePersonIdent` no longer allocate an entry object per header line or split strings.
- **vcs-store-files:** `withPacks` reads a packed object through `PackSet.getNow`: one promise for the read instead of one per layer.
