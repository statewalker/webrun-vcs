**`git fetch` and `git remote` as git does them: the opportunistic remote-tracking update, `followRemoteHEAD`, prune configuration and `--prune-tags`, `remote set-head -a`, `remote remove` and the new `remote rename`.**

- **vcs-commands, `FetchCommand`:** a fetch with explicit refspecs (`git fetch origin main`) also updates the remote-tracking refs the remote's `remote.<name>.fetch` maps the fetched refs to (git ≥ 1.8.4); FETCH_HEAD is unchanged. New `setRefmap(...refspecs)` (`--refmap`) maps them instead; an empty refmap turns the update off, and a refmap without explicit refspecs is refused with git's message. A configured fetch now creates `refs/remotes/<name>/HEAD` from the remote HEAD as git 2.48+ does, steered by `remote.<name>.followRemoteHEAD` / `fetch.followRemoteHEAD` (`create`, the default; `always`; `warn` and `warn-if-not-<branch>`, whose warning goes into `FetchResult.messages` in git's words; `never`); in a bare mirror the fetch moves HEAD itself. Pruning now follows `remote.<name>.prune` and `fetch.prune` when `setRemoveDeletedRefs` is not called, prunes before fetching (a remote branch `foo` that became `foo/bar` no longer conflicts), counts overlapping refspecs together and deletes in one ref batch (`fetch: prune`); a dry run reports what it would delete. New `setPruneTags(bool)` (`--prune-tags`, `remote.<name>.pruneTags`, `fetch.pruneTags`).
- **vcs-commands, `RemoteRemoveCommand`:** as git: removes the refs the remote's fetch refspecs map under `refs/remotes/` (not those another remote maps too, `HEAD` included) with their reflogs in one batch, unsets `branch.<b>.remote` / `branch.<b>.merge` of its branches and `branch.<b>.pushRemote` naming it, and `remote.pushDefault` naming it.
- **vcs-commands, new `git.remoteRename()` (`RemoteRenameCommand`, `git remote rename <old> <new>`):** renames the config section in place, rewrites the fetch refspecs writing under `refs/remotes/<old>/` (keeping the others, with git's warning in the result's `warnings`), updates `branch.<b>.remote` / `pushRemote` and `remote.pushDefault`, and moves `refs/remotes/<old>/*` in one batch with their reflogs and git's `remote: renamed …` line, re-pointing `refs/remotes/<new>/HEAD`. Errors in git's words.
- **vcs-commands, `RemoteSetHeadCommand`:** new `setAuto(true)` (`git remote set-head <name> -a`) asks the remote for its HEAD branch (errors "Cannot determine remote HEAD", "Multiple remote HEAD branches. …", "Not a valid ref: …" as git); setting HEAD on a remote with `followRemoteHEAD = always` turns it into `warn`, as git 2.48+. It now extends `TransportCommand` (credentials, headers, timeout).
- **vcs-transport:** `FetchClientOptions.opportunisticRefspecs` (refs the fetch took are also written through these, outside FETCH_HEAD) and `beforeFetch(remoteRefs)` (called after the listing, before any object or ref is written).
- **vcs-core:** `RefCommand.reflog` (`OwnReflogLine[]`): the reflog lines a command writes in place of its default line (git's `ref_transaction_update_reflog`); implemented by every batch-capable store.
- **vcs-store-files:** `GitWorkingCopyConfig.renameSection(old, new)` renames a section in place, as git's `rename_section`.
- **Follow-ups.** `RemoteRemoveCommand` refuses a remote without a config section with git's "No such remote: '<name>'" and changes nothing (it no longer returns undefined; breaking for callers that relied on the lenient JGit-era behaviour), keeps a ref any of whose sources a negative refspec excludes, and reports git's note on kept local branches in `getMessages()`. `RemoteSetHeadCommand.getMessages()` gives `set-head -a`'s report ("'origin/HEAD' is now created and points to 'main'", …). The fetch's `followRemoteHEAD=warn` messages carry git's hint lines (off with `advice.fetchRemoteHEADWarn=false`), a prune names the symbolic refs it leaves dangling, a refused prune goes into the new `FetchResult.errors` instead of failing the fetch, and a failing `refs/remotes/<name>/HEAD` update is ignored, as in git. The one-by-one move for stores without multi-ref batches never overwrites or loses a ref; the rename fallback for configs without `renameSection` copies every `remote.<old>.*` variable. `RefCommand.reflog` lines are checked (object ids, identity shape) and their control characters collapsed.
