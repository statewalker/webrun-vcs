**`rebase --rebase-merges`, and `%(trailers)`, `%(describe)`, `%S`, `%(count)` in pretty formats.**

- **Rebase:** `RebaseCommand.setRebaseMerges(true | "rebase-cousins" | "no-rebase-cousins" | false)` (default `rebase.rebaseMerges`) keeps the branch's merges as git 2.5x does. The todo list is git's `make_script_with_merges`: `label onto`, each branch picked from where it forked (`reset onto`, `reset <label>`, a cousin forked below the merge base kept on its fork point unless `rebase-cousins`), merged branches' tips labeled (by the branch pointing at them, else from the merge's message: `Merge branch 'x'`, `Merge pull request #n from x`, sanitised, numbered when taken), branch points labeled, `merge -C <merge> <label> # <oneline>`, `# Branch <label>` comments in the backup; the list written as the editing leaves it (comments dropped, blank lines kept and appended to `done`). The commands run as git's sequencer runs them: `label` (`refs/rewritten/<label>`, listed in `refs-to-delete` and deleted at the end or on abort), `reset` (`rebase (reset): '<label>'`), `merge` (merge-ort with the original message and author, `MERGE_HEAD`/`MERGE_MODE`, `rebase (merge): <subject>`; a fast-forward to the original merge when HEAD and the heads are its parents; nothing when the head is already in HEAD; a conflict stops with `Could not apply <abbrev>... <label> # <oneline>`, `--continue` commits the merge with both parents; `merge -c` re-commits the message cleaned up as an edited one). Todo files with `label`/`reset`/`merge` (and their `l`/`t`/`m` abbreviations) written by native git are resumed. An octopus (`merge -C <merge> <label> <label>...`) runs as git runs `git merge -s octopus --no-ff -F MERGE_MSG`: git-merge-octopus's messages, `ORIG_HEAD`, the reflog line `merge <heads>: Merge made by the 'octopus' strategy.`; its conflicts with the last head (`MERGE_HEAD` listing every head, `--continue` commits all the parents) or its giving up ("Should not be doing an octopus.") stop the rebase there. `reset [new root]` is refused. An unknown `rebase.rebaseMerges` mode dies with git's `fatal: Unknown rebase-merges mode: <value>`.
- **Rebase, also without merges:** "Current branch <b> is up to date" ("HEAD is up to date" when detached) only where git's `can_fast_forward` says so: upstream in HEAD's history *and* no merge on the first-parent line since, so a branch with merges on top of its upstream is rebased (linearized, rebuilt with `--rebase-merges`); forced (date options, `--signoff`) it says "..., rebase forced." and rebases. The first picks whose parent is where the rebase starts are skipped as git's `skip_unnecessary_picks` skips them (HEAD starts at the last, they go to `done`); later ones are fast-forwarded (git's `allow_ff`, `rebase: fast-forward`) unless the dates are rewritten or the commits signed off; comment and blank lines of a todo file are kept and appended to `done`; a commit empty from the start is listed `pick <id> # <subject> # empty`; `--continue` records the stopped commit in `rewritten-list` whether or not it commits, and leaves `REBASE_HEAD` (as git) when it continued the last command; `--skip` runs as git's (sequencer_continue): the stopped commit mapped to HEAD in `rewritten-list`, `AUTO_MERGE` removed, `REBASE_HEAD` left after the last command; a pick that commits or is dropped removes `MERGE_MSG` (what a merge already in HEAD left); abort and skip remove `MERGE_HEAD`/`MERGE_MODE`.
- **Rebase `--signoff`:** `RebaseCommand.setSignoff(true)` (kept in `rebase-merge/signoff`, implies `--force-rebase`) appends git's `Signed-off-by: <committer>` to each pick as `append_signoff` does (unless the trailer block already ends with it), cleans the message up as whitespace, and never fast-forwards; recreated merges are not signed off, as in git. `appendSignoff` is exported from the trailers module.
- **Pretty formats:** `%(trailers[:only,unfold,keyonly,valueonly,separator=,key_value_separator=,key=])` follows git 2.5x's trailer.c (the block rules: all trailers, or a git-generated `Signed-off-by: ` / `(cherry picked from commit ` with a quarter trailers; continuation lines, comments, the scissors line, `://` not a separator, `trailer.separators`, `trailer.<name>.key`); `trailerConfigOf(workingCopy)` reads the configuration and `appendTrailers` / `formatTrailersOf` are exported. `%(describe[:tags,abbrev=,match=,exclude=])` runs git describe's search (`createDescriber`: nearest annotated tag by commit distance, lightweight with `tags`, ten candidates, misnamed tags in long form). `%S` shows `PrettyFormatOptions.source` and `%(count)`/`%(total)` `PrettyFormatOptions.count` (git 2.5x; without, git's "not supported by this command"). `rebase.instructionFormat` reads the trailer configuration and describes with the repository's tags.
