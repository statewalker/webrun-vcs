**`rebase --rebase-merges`, and `%(trailers)`, `%(describe)`, `%S`, `%(count)` in pretty formats.**

- **Rebase:** `RebaseCommand.setRebaseMerges(true | "rebase-cousins" | "no-rebase-cousins" | false)` (default `rebase.rebaseMerges`) keeps the branch's merges as git 2.5x does. The todo list is git's `make_script_with_merges`: `label onto`, each branch picked from where it forked (`reset onto`, `reset <label>`, a cousin forked below the merge base kept on its fork point unless `rebase-cousins`), merged branches' tips labeled (by the branch pointing at them, else from the merge's message: `Merge branch 'x'`, `Merge pull request #n from x`, sanitised, numbered when taken), branch points labeled, `merge -C <merge> <label> # <oneline>`, `# Branch <label>` comments in the backup; the list written as the editing leaves it (comments dropped, blank lines kept and appended to `done`). The commands run as git's sequencer runs them: `label` (`refs/rewritten/<label>`, listed in `refs-to-delete` and deleted at the end or on abort), `reset` (`rebase (reset): '<label>'`), `merge` (merge-ort with the original message and author, `MERGE_HEAD`/`MERGE_MODE`, `rebase (merge): <subject>`; a fast-forward to the original merge when HEAD and the heads are its parents; nothing when the head is already in HEAD; a conflict stops with `Could not apply <abbrev>... <label> # <oneline>`, `--continue` commits the merge with both parents; `merge -c` re-commits the message cleaned up as an edited one). Todo files with `label`/`reset`/`merge` (and their `l`/`t`/`m` abbreviations) written by native git are resumed. Octopus merges and `reset [new root]` are refused.
- **Rebase, also without merges:** a pick whose parent is already HEAD is fast-forwarded (git's `allow_ff`, `rebase: fast-forward`) unless the dates are rewritten; comment and blank lines of a todo file are kept and appended to `done`; `--continue` records the stopped commit in `rewritten-list` whether or not it commits, and leaves `REBASE_HEAD` (as git) when it continued the last command; abort and skip remove `MERGE_HEAD`/`MERGE_MODE`.
- **Pretty formats:** `%(trailers[:only,unfold,keyonly,valueonly,separator=,key_value_separator=,key=])` follows git 2.5x's trailer.c (the block rules: all trailers, or a git-generated `Signed-off-by: ` / `(cherry picked from commit ` with a quarter trailers; continuation lines, comments, the scissors line, `://` not a separator, `trailer.separators`, `trailer.<name>.key`); `trailerConfigOf(workingCopy)` reads the configuration and `appendTrailers` / `formatTrailersOf` are exported. `%(describe[:tags,abbrev=,match=,exclude=])` runs git describe's search (`createDescriber`: nearest annotated tag by commit distance, lightweight with `tags`, ten candidates, misnamed tags in long form). `%S` shows `PrettyFormatOptions.source` and `%(count)`/`%(total)` `PrettyFormatOptions.count` (git 2.5x; without, git's "not supported by this command"). `rebase.instructionFormat` reads the trailer configuration and describes with the repository's tags.
