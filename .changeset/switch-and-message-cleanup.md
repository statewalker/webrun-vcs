**`git switch`, `checkout --detach` and `@{-N}`, `branch -c`, git's message cleanup, fetch and pull reflog actions with their options.**

- **vcs-commands:**
  - New `SwitchCommand` (`git.switch()`), with `git switch`'s rules and messages. It switches to `<branch>` or to `-`, creates a branch with `-c`/`-C <new> [<start>]` (`setCreateBranch`, `setForceCreateBranch`, `setStartPoint`), detaches with `--detach [<commit>]`, and starts an empty unborn branch with `--orphan <new>`. It supports `--guess`/`--no-guess` (a name only a remote-tracking branch has creates the local branch tracking it; `checkout.defaultRemote` picks among several remotes), `--track`/`--track=inherit`/`--no-track` (`TrackMode`), `--discard-changes` (untracked files still protected), `-f` and `--ignore-other-worktrees`. `SwitchRefusedError` carries git's refusals: `fatal: a branch is expected, got tag 'v1'` (also `commit`, `remote branch`) with git's hint, `invalid reference`, `a branch named 'x' already exists`, `cannot switch branch while merging` (also while rebasing, cherry-picking or reverting), and the option conflicts. `--merge` is not supported.
  - `CheckoutCommand` gains `setDetach` (`checkout --detach [<commit>]`, logged `checkout: moving from main to HEAD`), `-` and `@{-N}` as names (the reflog line names the branch they stand for), `setTrack` and `setGuess`. A branch it creates now tracks a remote-tracking start point as `branch.autoSetupMerge` says, and is created after the worktree switch, as git does it. Names resolve as revisions (`HEAD~1`, a peeled annotated tag, `origin/dev`).
  - Rev parsing (`resolveRef`) understands `@{-N}`: it reads HEAD's reflog for `checkout: moving from` lines. It also understands `refs/remotes/<name>` and `refs/remotes/<name>/HEAD`.
  - New `CopyBranchCommand` (`git.branchCopy()`, `branch -c`/`-C`): it copies the branch, its reflog (with git's `Branch: copied refs/heads/a to refs/heads/b` line) and its `branch.<name>.*` section. HEAD stays where it is. `branch -m` now renames the branch's configuration section, and `branch -d` drops it, as git does.
  - Messages follow git's `-m`. `commit` ends the last line, then cleans up as `whitespace` (`commit.cleanup` and the new `setCleanupMode(CleanupMode.*)` choose otherwise). `merge` cleans up the same way without ending the line first. `tag` uses `strip` by default (comment lines go, `core.commentChar`) and adds no newline in `verbatim` mode. `--amend` without a message cleans up the amended message again. A commit whose message cleans up to nothing is refused (`Aborting commit due to empty commit message.`) unless `setAllowEmptyMessage(true)`. `stripspace` (git's `strbuf_stripspace`) is exported.
  - Fetch reflog lines carry the options git's argv would: `fetch --atomic --force --prune --prune-tags --tags --depth=<n> --unshallow --append --no-write-fetch-head --refmap=<spec> <remote> <refspec>...`. Pull lines add `--ff`/`--no-ff`/`--ff-only`, `--strategy=<s>` and `--tags`/`--no-tags`.
  - **Behaviour change:** a commit or tag made with a message that has no trailing newline now stores one, as native git does, so its id changes. Callers that compared `commit.message` with the string they passed now see `"<message>\n"`.
- **vcs-store-files:** `GitWorkingCopyConfig.copySection(old, new)`, git's `git_config_copy_section`: the copy goes right after the section, with its lines kept.
