**`git switch`, `checkout --detach` and `@{-N}`, `branch -c`, git's message cleanup, fetch and pull reflog actions with their options.**

- **vcs-commands:**
  - New `SwitchCommand` (`git.switch()`), with `git switch`'s rules and messages. It switches to `<branch>` or to `-`, creates a branch with `-c`/`-C <new> [<start>]` (`setCreateBranch`, `setForceCreateBranch`, `setStartPoint`), detaches with `--detach [<commit>]`, and starts an empty unborn branch with `--orphan <new>`. It supports `--guess`/`--no-guess` (a name only a remote-tracking branch has creates the local branch tracking it; `checkout.defaultRemote` picks among several remotes), `--track`/`--track=inherit`/`--no-track` (`TrackMode`; any of them without `-c` names the new branch after the remote-tracking one, as git does), `--discard-changes` (untracked files still protected), `-f` and `--ignore-other-worktrees`. `SwitchRefusedError` carries git's refusals: `fatal: a branch is expected, got tag 'v1'` (also `commit`, `remote branch`) with git's hint, `invalid reference`, `a branch named 'x' already exists`, `cannot switch branch while merging` (also while rebasing, cherry-picking or reverting), and the option conflicts. `--merge` is not supported.
  - `CheckoutCommand` gains `setDetach` (`checkout --detach [<commit>]`, logged `checkout: moving from main to HEAD`), `-` and `@{-N}` as names and as start points (the reflog lines, `branch: Created from feat` included, name the branch they stand for, and that branch is tracked), `setTrack` and `setGuess`. Only the name as given is guessed into a remote-tracking branch, so `-` naming a deleted branch is refused. `setName("HEAD")` without `setDetach` leaves HEAD as it is. A branch it creates now tracks a remote-tracking start point as `branch.autoSetupMerge` says, and is created after the worktree and the index are switched, as git does it; `--track` from a start point that is no branch is refused before the branch is made. Names resolve as revisions (`HEAD~1`, a peeled annotated tag, `origin/dev`).
  - Rev parsing (`resolveRef`) understands `@{-N}`: it reads HEAD's reflog for `checkout: moving from` lines. It also understands `refs/remotes/<name>` and `refs/remotes/<name>/HEAD`.
  - New `CopyBranchCommand` (`git.branchCopy()`, `branch -c`/`-C`): it copies the branch, its reflog (with git's `Branch: copied refs/heads/a to refs/heads/b` line) and its `branch.<name>.*` section. HEAD stays where it is. `branch -m` now renames the branch's configuration section, and `branch -d` drops it, as git does.
  - Messages follow git's `-m`. `commit` ends the last line, then cleans up as `whitespace` (`commit.cleanup` and the new `setCleanupMode(CleanupMode.*)` choose otherwise). `merge` cleans up the same way without ending the line first. `tag` uses `strip` by default (comment lines go, `core.commentChar`), adds no newline in `verbatim` mode, refuses `CleanupMode.DEFAULT` by name as git does, and `setMessage("")` alone makes an annotated tag. The comment character is the last of `core.commentChar`/`core.commentString` set; for a commit, `auto` picks one no line of the message starts with. A commit of a prepared `MERGE_MSG` honours `commit.cleanup` and the comment character. A merge whose message cleans up to nothing is refused (`Empty commit message.`), the merge state left for `commit`. `--amend` without a message cleans up the amended message again. A commit whose message cleans up to nothing is refused (`Aborting commit due to empty commit message.`) unless `setAllowEmptyMessage(true)`. `stripspace` (git's `strbuf_stripspace`) is exported.
  - Fetch reflog lines carry the options git's argv would: `fetch --atomic --force --prune --prune-tags --tags --depth=<n> --unshallow --append --no-write-fetch-head --refmap=<spec> <remote> <refspec>...`. Pull lines add `--ff`/`--no-ff`/`--ff-only`, `--strategy=<s>` and `--tags`/`--no-tags`.
  - **Behaviour change:** a commit or tag made with a message that has no trailing newline now stores one, as native git does, so its id changes. Callers that compared `commit.message` with the string they passed now see `"<message>\n"`.
- **vcs-store-files:** `GitWorkingCopyConfig.copySection(old, new)`, git's `git_config_copy_section`: the copy goes right after the section, with its lines kept (a variable on the header line is not copied). `renameSection` and `unsetSection` edit the file's lines as git's `config.c` does: headers are matched as written, a rename onto an existing section keeps both in file order, and a removed section's comments and blank lines go with it. New `getLastOf(keys)`: the value set last among several keys.
