**Fetch and push summaries as git prints them, `rebase.instructionFormat`, grafts and replace refs in history walks.**

- **vcs-transport:** the ids of fetch and push summaries (`a..b`, `+ a...b`) are abbreviated as git's find_unique_abbrev under `core.abbrev` (new `abbrev` option of fetch and push; `RepositoryFacade.abbrevLengths`, implemented by `createRepositoryFacade`), no longer cut to 7 digits. Fetch and push results carry `abbrevLengths` and `summaryWidth` (git's `transport_summary_width`). `formatPushStatus` renders git's push report (`To <url>`, ` * [new branch]  main -> main`, ` ! [rejected]  main -> main (fetch first)`, `Everything up-to-date`); `fetchUpdateDisplay`, `formatFetchDisplay` and `fetchRefcolWidth` render git's fetch lines (full and compact formats). A forced tag update's summary is now `[tag update]` (git's `t` line), and a new ref is named after the remote ref (`[new tag]` for a remote tag), as git does. `FetchClientResult.backfilledTags` lists the tags found in the fetched history.
- **vcs-commands:** `FetchResult.display` and `PushResult.display` hold the stderr lines git prints for the refs. `rebase.instructionFormat` formats the todo lines (and the `Could not apply` line) through git's pretty format, `# ` put before a format that does not start with `#` (git 2.45+); the todo's text is kept as written when read back. `formatCommitPretty` is git's user format (`%H %h %T %t %P %p`, `%an %ae %al %ad %aD %ar %at %ai %aI %as` and the committer's, `%s %f %b %B %e`, `%n %% %x..`, colors, `%+ %- % ` magic). Log, rev-list, revision parents (`HEAD~2`) and merge bases apply replace refs (`refs/replace/<id>`, `GIT_REPLACE_REF_BASE`) and grafts (`info/grafts`), as git's parse_commit does; `setUseReplaceRefs(false)` is `--no-replace-objects`, and `core.useReplaceRefs=false` and `GIT_NO_REPLACE_OBJECTS` turn them off. `fsck` walks grafted parents (a parent grafted away is dangling; `bad graft data` and `bad graft parent` errors as git's).
- **vcs-core:** `loadObjectReplacements`, `createReplacedCommits`, `parseGraftFile` and `replacementOf`; `Refs.readGrafts` (optional) reads `info/grafts`.
- **vcs-store-files:** the file ref store and linked worktrees' refs read `info/grafts`.
- **vcs-working-tree / vcs-utils-node:** `GitHostEnvironment.noReplaceObjects` and `replaceRefBase`, read from `GIT_NO_REPLACE_OBJECTS` and `GIT_REPLACE_REF_BASE`.
- **Replace refs and grafts in every porcelain read:** commands read commits, trees, blobs and annotated tags through replace refs and grafts as git does (merge bases and fast-forward decisions of merge, rebase, cherry-pick, revert, pull; the trees checkout, switch, reset, status, diff and merge read; `branch --contains`/`--merged`; commit parent checks), while fsck and gc read the objects as stored (`GitCommand.readsReplacedObjects`). vcs-core adds `createReplacedTrees`, `createReplacedBlobs`, `createReplacedTags` and `overlayMethods`; a replace ref's object is the last component of its name (`refs/replace/foo/<id>`), an empty `GIT_REPLACE_REF_BASE` makes every ref a candidate, `GIT_GRAFT_FILE` names the grafts file (`GitHostEnvironment.graftFile`), and a shallow commit has no parents even when `info/grafts` gives it some. `replacementMessages()` returns what git prints while reading them (`bad replace ref name`, the grafts advice, `bad graft data`); rev-parse puts them in its warnings.
- **gc keeps what grafts reach:** gc, repack and `GcOrchestrator` walk a grafted commit's grafted parents as well as its recorded ones (`listObjects` and `collectReachableObjects` take `grafts`; `readGraftParents`), as git's `repack --keep-true-parents` and prune together keep both; before, an old history reachable only through `info/grafts` was deleted.
- **Fetch:** when a ref update is refused (non-fast-forward, a tag it would clobber) every line is printed with a summary width of 0, as git 2.5x does; a ref the store refuses to write keeps its summary with `!` and `(unable to update local ref)` (`FetchRefUpdate.storeError` holds the store's reason); a fetch into a branch a worktree has checked out dies before fetching (`FetchIntoCheckedOutBranchError`, `fatal: refusing to fetch into branch '<ref>' checked out at '<path>'`) unless `setUpdateHeadOk(true)` (which pull passes); a refspec destination outside `refs/` is a branch (`main:side` writes `refs/heads/side`).
- **Push:** the report names the source as written (`HEAD~1 -> y`, `HEAD -> z`, an object id; `PushRefUpdate.source`).
- **Pretty formats:** `%d`, `%D` and `%(decorate:…)` (`loadRefDecorations`, with git log's default filter or the sequencer's none), `%m`, `%ah`, `%G?` and the other `%G` parts, `%N`, `%gd %gs %gn…`, padding and truncation (`%<(N)`, `%>(N)`, `%><(N)`, `%>>(N)`, `|` columns, `trunc`/`ltrunc`/`mtrunc`), `%w(…)` wrapping, `%C(always,…)` and colors when asked; `%x80`–`%xff` write raw bytes (the byte strings' U+DC80–U+DCFF); git's ASCII-only isspace (a no-break space is never trimmed, in subjects and in `info/grafts`).
