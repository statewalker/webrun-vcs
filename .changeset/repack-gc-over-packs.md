**Changed: `repack()` is `git repack -a -d` over the pack set, streamed end to end.** `repack(backend)` lists every object reachable from the refs, HEAD, the reflogs and the index (`listObjects`), streams them through `writePack` (reusing stored whole objects and deltas, searching deltas for the rest) straight into `PackSet.install`, and only then removes the packs the new one replaces and the loose objects a pack now holds (`prunePacked`, git's `prune-packed`). No pack is held in memory. Packs with a `.keep` file stay, and their objects are not copied (git's `--honor-pack-keep`). `repack({ ...backend, all: false })` is `git repack -d`: the reachable loose objects go into a new pack, existing packs are untouched. Unreachable loose objects are never packed. The options are `all`, `deltaSearch`, `reuseDeltas`, `reuseObjects`, `bigFileThreshold` and `dryRun`; the result adds `packsRemoved` and `keptPacks`. `repack({ looseStorage, packDirectory })` no longer exists.

**Changed: `gc()` is `git gc`.** It packs refs (`packRefs`, default true), repacks what is reachable into one pack (`repack`, default true), prunes unreachable loose objects last modified more than `pruneExpireMs` ago (default two weeks, git's `gc.pruneExpire`; `0` is `--prune=now`) and sweeps loose and pack temporaries. Objects reachable only from a reflog or the index are kept. Unreachable objects already packed are dropped by the repack, as `git repack -a -d` does (no cruft pack). The result adds `keptRecentObjects`, `refsPacked` and `repack`. Breaking: unreachable loose objects younger than two weeks are no longer removed by default.

**New in vcs-store-files:** `listReachableObjects` and `collectReachabilityRoots` (refs, HEAD, reflogs, index), `prunePacked`, `RepackTarget`, `DEFAULT_PRUNE_EXPIRE_MS`. `createGitFilesBackend` returns `files` and `gitDir`, so its result can be passed to `repack()` and `FileGcStrategy` as is. `FileGcStrategy(backend)` compacts with `repack({ all: false })` and reads its stats from the pack set.

**Fixed in vcs-core:** a `PackSet` whose pack file disappeared (removed by a repack in another backend or by native git) rescans the directory at once, whatever the rate limit, so a concurrent reader finds the replacement pack instead of reporting the object missing.

**Removed (legacy pack code):** in vcs-core, `indexPack` / `verifyPackChecksum` (`pack-indexer`; use `installPack`), `PendingPack`, the `GitPackStore` interface, `CombinedRawStorage`, `GitFilesBlobDeltaApi`, `GitFilesDeltaApi`, `GitFilesTreeDeltaApi`, `GitFilesCommitDeltaApi` and `DeltaStore.loadObject`; in vcs-store-files, `PackDirectory`, `PackReader`, `PackDeltaStore`, `PackConsolidator`, `GitPackStoreImpl` / `createGitPackStore`, `RandomAccessDeltaReader`, `DirectPackObjectReader`, `PackDirectoryAdapter`, and `packDirectory` from the backend result. `createGitFilesHistory(config)` takes `packs` instead of `packDeltaStore`; its `delta` is the new read-only `PackSetDeltaApi` (which packed objects are deltas, their chains; `deltifyBlob` throws, as git writes deltas only through `repack()`). `GitFilesHistoryOptions.enableDeltas` is gone.

**Changed: `GCController` gets a size cap.** `maxDeltaBlobSize` (default 16 MiB) keeps blobs larger than that out of deltification in `quickPack` and `runGC`. The controller serves the memory, KV and SQL delta stores; Git file repositories use `repack()` and `gc()`.
