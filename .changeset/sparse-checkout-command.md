**`git sparse-checkout`, and index-writing commands that honour the sparse checkout.**

- New `SparseCheckoutCommand` (`git.sparseCheckout()`): `init`, `set`, `add`, `list`, `reapply`, `disable` and `check-rules`, from git's command line (`setArguments`) or typed setters. Cone-mode pattern files are written byte for byte as git's `write_cone_to_file` writes them, non-cone patterns verbatim; `core.sparseCheckout` and `core.sparseCheckoutCone` go to `config.worktree` with `extensions.worktreeConfig` set; directories are checked as git's `sanitize_paths` checks them; messages and exit statuses are git's. The sparse index is not supported (`--sparse-index` is refused).
- Applying the patterns (git's `update_sparsity`): entries going out of the checkout become skip-worktree and their files are removed with the directories left empty, a changed file stays with git's "not up to date" warning, entries coming back are written.
- `checkout`/`switch`, `reset --hard/--merge/--keep`, `merge`, `cherry-pick`, `revert`, `rebase`, `am` and `clone --sparse` (new `CloneCommand.setSparse`) apply the patterns as unpack-trees does, in its order: entries that stay outside (skip-worktree ones, new ones) are neither checked nor written, so an untracked, ignored or changed file at such a path is kept; files leaving the patterns are checked against the index as the command found it (racily clean changes included) before anything is written. A conflicted path's file is written whatever the patterns say where its entry was outside the checkout (skip-worktree, or new), as merge-ort's `record_conflicted_index_entries` does; one whose entry was in the checkout and now leaves it is unlinked as any leaving file (its content is in the index stages). An ignored file where an entry comes back into the patterns is overwritten (a directory holding untracked files keeps it out, silently, as unpack-trees' ERROR_NOT_UPTODATE_DIR); a directory where a leaving file cannot be unlinked prints git's "unable to unlink" warning. The warnings are on the results (`CheckoutResult.warnings`, `MergeResult.warnings`, `CherryPickResult.warnings`, `RevertResult.warnings`, `ResetCommand.getWarnings()`).
- In cone mode `sparse-checkout set/add/reapply/init` remove the directories outside the cone left with ignored files only and warn about those holding untracked files (git's `clean_tracked_sparse_directories`); a file reached through a symlinked directory is kept with the "not up to date" warning, never removed.
- `sparse-checkout set/add/reapply` (`update_sparsity`) never treat an ignored file as expendable: one where an entry comes back is kept and reported, a directory holding one keeps the entry out.
- The ignore rules read a `.gitignore` missing from the worktree from the index when its entry is skip-worktree, as git's `add_patterns` does (`read_skip_worktree_file_from_index`), for status, add, clean and every walk alike: `clean_tracked_sparse_directories` keeps a file such a `.gitignore` un-ignores (new `Worktree.setSkipWorktreeIgnoreReader`, installed by working copies).
- `reset --hard` and `checkout -f` record the stat of the files they write (git's `check_updates`), so `diff-files` and a following sparse update find them clean; `reset --hard` removes the directories its deletions leave empty, as git's `unlink_entry` does.
- `rm` matches git's pathspecs (`rm --cached -r .` removes everything) and checks them as `cmd_rm` does before anything changes: a pattern naming a directory needs `-r` (new `RmCommand.setRecursive`; "fatal: not removing 'd' recursively without -r"), one matching nothing dies ("fatal: pathspec 'x' did not match any files") unless `setIgnoreUnmatch(true)`; with 2.43 compatibility an element that named an entry exactly matches no later entry (`rm 'b*'` removes only `b*`).
- `rm` without `--force` refuses, before anything changes, to drop content only the index holds, as git's `check_local_mod` does (new `RmCommand.setForce`): with `--cached` an entry whose staged content differs from both its file and HEAD (an intent-to-add one excepted); without it also staged changes against HEAD and local modifications, with git's messages (singular or plural, each with its hint unless `advice.rmHints` is off). Without `--cached` the files are removed too and the directories they leave empty pruned (git's `remove_path`); a directory standing at a file stops the first removal with "fatal: git rm: 'f': Is a directory".
- A stopped merge's autostash (`MERGE_AUTOSTASH`) is kept on `refs/stash` with git's "Autostash exists; creating a new stash entry." lines by an "Already up to date." merge, the new `merge --quit` (`MergeOperation.QUIT`), `reset`, a branch switch and `am` (git's `remove_merge_branch_state`); the lines are in `MergeResult.output`, `ResetCommand.getWarnings()` and `CheckoutResult.warnings`.
- A refused merge's restore (`restore_state`'s `read-tree --reset -u` and `stash apply --index`) removes a directory standing at any tracked file, a nested repository included, before writing the file (a symlink to a directory is replaced as a file), so a staged change there is restored instead of failing with "would lose untracked files"; a file that cannot be written is reported, never thrown.
- A conflict whose stage-0 entry stays skip-worktree (a rebase or merge pick the two trees agree on, a delete on their side) has its file written, as `record_conflicted_index_entries` checks it out; `stash apply` honours the sparse checkout as unpack-trees does (files leaving the patterns unlinked, skip-worktree flags set, `StashApplyResult.warnings`).
- A local change is seen through a symbolically linked directory (`verify_uptodate`'s `lstat` follows it), so `checkout`/`reset --merge` refuse to switch such a file.
- A cherry-pick or revert that commits removes `CHERRY_PICK_HEAD` and `MERGE_MSG` (git's `do_commit`), a stopped empty pick's included; an "Already up to date." merge removes `AUTO_MERGE` and the other merge state (`remove_merge_branch_state`); a refused merge whose saved changes equal HEAD (a tracked file replaced by a directory, which `stash create` passes over) records no `AUTO_MERGE`, and its reset writes the file over that directory as git's does.
- `clearSkipWorktreeFromPresentFiles` stats in batches, a missing sparse directory costing one stat.
- `diff` reads skip-worktree entries whose files are present as in the checkout (without writing the index); `rm` refuses paths outside the patterns with git's advice (`RmFailedError`) unless `setSparse(true)`.
- `parseSparseCheckoutPatterns` reports git's warnings for patterns cone mode cannot read (`warnings`), and gives the cone's hashsets (`coneSets`) and the lines read; new `sparsePatternsFromLines`, `sparsePatternsFromCone`, `splitPatternLines`.
- `GitWorkingCopyConfig.set`/`add` write the variable name as spelled (`sparseCheckout`), as git does.
- `rm` passes over every skip-worktree entry unless `setSparse(true)`, with or without `core.sparseCheckout`, giving git's "outside of your sparse-checkout definition" advice as `cmd_rm` does; a path removed loses every stage (an unmerged one's kept as resolve-undo, git's `remove_file_from_index`).
- `rm` refuses a populated submodule whose own worktree holds modified, staged or untracked files (ignored ones aside) with "the following file has local modifications" (git's `bad_to_remove_submodule`); a clean one's directory is removed where its repository lives in the superproject (a gitfile), its `.gitmodules` section removed and the file staged again (`remove_path_from_gitmodules`, `stage_updated_gitmodules`), and a `.gitmodules` holding unstaged changes stops it ("please stage your changes to .gitmodules or stash them to proceed"). A submodule with its own `.git` directory keeps its directory (git absorbs the repository first).
- `rm` sees a path reached through a symbolically linked leading directory as `lstat` does: a file there is a local modification, a directory stops the removal ("Is a directory"); nothing is ever removed through the link. A removal failing after another one succeeded is passed over (`RmResult.warnings`) and the index written, as git does.
- `stash create` (and so a refused merge's `save_state`) takes an assume-unchanged entry from the index without looking at its path, a path beyond a symbolic link included, so such a merge returns FAILED and resets instead of throwing.
