**Status sees the worktree; `stashCreate()` works without a provider; stash apply follow-ups.**

- **vcs-commands (breaking behaviour):** `git.status()` compares the worktree with the index as `git status` does: modified, deleted and type-changed files (`modified`, `missing`), untracked files (`untracked`, `-uall`), ignored ones with `setIgnored(true)` (`ignored`), unmerged entries with `conflictingStageState`. Files are compared through the index stat; a racily clean entry (modified at or after the index was written) is re-hashed, as git does; links are 120000, the executable bit counts only where `core.filemode` trusts it, `core.symlinks=false` keeps a link checked out as a file. `isClean()` now also requires no unstaged change and no untracked file; `hasUncommittedChanges()` counts unstaged changes. New `status.files` (one entry per porcelain line) and `formatStatusPorcelain(status, 1 | 2)` print `git status --porcelain[=v2] --untracked-files=all` (renames are not detected). `setUntracked(false)` is `-uno`.
- **vcs-commands:** `git.stashCreate()` on a working copy with an index and a worktree uses a built-in provider (`WorkingCopyStashProvider`): the index tree, the worktree tree and (`setIncludeUntracked(true)`, new `setIncludeIgnored(true)` for `--all`) the untracked tree as `git stash push` builds them, then `git clean -fd` (with `-u`), `git reset --hard` (only differing paths are written; untracked files stay) and, with new `setKeepIndex(true)`, the index tree checked out again. "No local changes to save" (untracked files only count with `-u`) returns undefined; an index with unmerged entries is refused (`<path>: needs merge`). Without a worktree it still throws `StoreNotAvailableError`. `StashWorkingTreeProvider.hasLocalChanges`/`getUntrackedTree`/`resetHard` take optional options (`StashResetOptions`).
- **vcs-commands (stash apply):** move-aside names (`<path>~<side>`) are compared case-insensitively with `core.ignorecase`; a gitlink moved aside keeps its stage-2 entry, gets an empty directory at the new path and its old directory is removed only if empty (as git); a conflict that neither writes nor removes the worktree file (rename/rename, rename/delete on our side, binary) no longer refuses an unstaged edit there (git keeps it); a file standing where a stashed untracked file goes is refused with git's message (`<path> already exists, no checkout` / `error: could not restore untracked files from stash`), whether it is untracked or staged.
- **vcs-working-tree:** new `compareWithWorktree`, `diffIndexWithWorktree`, `findUntrackedFiles`, `trackedUnder`, `directoriesOf`, `defaultModeTrust` (the worktree side of status) and `createIndexTree`, `createWorktreeTree`, `createUntrackedTree`, `hasTrackedChanges`, `storeFlatTree`, `assertNoUnmergedEntries` (the stash trees, shared by `GitStashStore` and `stashCreate()`).
- **vcs-store-files:** `GitStashStore.push` builds its trees with the shared helpers: nested paths, deleted files and untracked files in subdirectories are stored as git stores them (they were flattened or kept); new `trust` option.
