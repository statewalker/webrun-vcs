**Repositories in a format we cannot read are refused when opened, as git refuses them; gc keeps more roots, verifies blobs, and deletes nothing in precious-objects repositories and partial clones.**

- **vcs-store-files (repository format):** `createGitFilesBackend` (and so `InitCommand`, `createGitFilesHistoryFromFiles` and everything that opens a repository through them) checks `core.repositoryformatversion` and `extensions.*` first, as git's `check_repository_format`: a version above 1, an unknown extension in a version-1 repository, a version-1-only extension in a version-0 one, and the formats we do not implement (`extensions.refStorage = reftable`, `extensions.objectFormat = sha256`, `extensions.compatObjectFormat`) throw the new `UnsupportedRepositoryFormatError`, before anything is read or written. `noop`, `noop-v1`, `worktreeConfig`, `relativeWorktrees`, `objectFormat = sha1`, `refStorage = files`, `preciousObjects` and `partialClone` open. New exports: `readRepositoryFormat`, `checkRepositoryFormat`, `assertObjectsDeletable`, `RepositoryFormat`. `GitWorkingCopyConfig` gains `listKeys(prefix)`.
- **vcs-store-files (gc):** in a repository with `extensions.preciousObjects`, `gc()` only packs refs (as `git gc` skips repack and prune there), and `repack()` and `GcOrchestrator` with `FileGcStrategy` throw ("cannot prune in a precious-objects repo"). **Partial clones now abort gc:** a repository with `extensions.partialClone` or a remote with `remote.<name>.promisor = true` (what `git clone --filter` writes) makes `gc()`, `repack()` and the orchestrator throw `UnsupportedRepositoryFormatError` before deleting anything; promisor objects are not supported. **Repositories with alternates also abort gc**: the objects they borrow through `objects/info/alternates` are not read here, so `gc()`, `repack()` and the orchestrator throw `UnsupportedRepositoryFormatError` with nothing deleted (since the previous release the orchestrator's strict walk already threw `MissingObjectError` there as soon as a local object referred to a borrowed one).
- **vcs-store-files (gc roots):** `collectReachabilityRoots` also keeps the autostash of a merge or rebase in progress (`MERGE_AUTOSTASH`, `rebase-merge/autostash`, `rebase-apply/autostash`, which nothing else names until `--abort` or `--continue` applies them) and the per-worktree refs of linked worktrees (`worktrees/<name>/refs/bisect/*`, `refs/worktree/*`, `refs/rewritten/*`), which git 2.43's own gc drops.
- **vcs-core (strict walk):** `collectReachableObjects` with `missing: "throw"` reads every reachable blob to its end (streamed) and checks its length against its header (new `CollectReachableOptions.verifyBlobs`, on by default when strict), so a truncated loose blob aborts `GcOrchestrator.run` before anything is pruned. Objects beyond the shallow boundary are now optional: they are walked last and leniently, so a stored parent of a shallow commit whose tree is missing (or corrupt) no longer aborts gc.

**Review fixes.** `extensions.submodulePathConfig` (git 2.56, version 1) is accepted. Format values are compared case-sensitively as git does (`objectFormat = SHA1` and `refStorage = Files` are invalid), a bare `partialClone` key is refused for its missing value, and numbers are parsed as `git_parse_int` (`01`, `0x1`, `k`/`m`/`g` units). New `GcRunOptions.verifyBlobs` (default true) turns blob verification off; pruning only removes unreachable objects, so turning it off risks no data loss.
