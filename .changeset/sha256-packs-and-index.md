**SHA-256 repositories read and write packs and the index file, so gc, repack, prune, status, add and commit work in them.**

- **vcs-core:** packs take the store's object format: `openPack`/`openPackSet`/`installPack`/`unpackObjects`/`writePack` accept `objectFormat` (default: SHA-1, or the store's `objectFormatOf(objects)` for `unpackObjects`/`writePack`/`listObjects`). In SHA-256 a pack's trailer and every REF_DELTA base are 32 bytes, its `.idx` is version 2 with 32-byte ids and SHA-256 checksums (git writes v2 for SHA-256 too), its `pack-<64-hex>` names are recognised, and `.rev` and `.mtimes` carry hash id 2 and SHA-256 checksums (`encodeReverseIndex`/`encodePackMtimes` take the width from the pack checksum, the parsers from the header's hash id). `readPackIndex(bytes, rawLength)`, `writePackIdx` (width from the checksum), `PackIndex.rawLength`, `packEntryOrder`/`packIdxLookups`/`parsePackEntryHead` (`rawLength`), `scanTreeEntry(data, at, raw)`, `ObjectIdFlags(capacity, raw)`. A SHA-256 pack set uses no multi-pack-index and no bitmap (their readers hold 20-byte ids).
- **vcs-working-tree:** the index file in the repository's format (`ParseIndexOptions.objectFormat`, `encodeIndexFile(..., objectFormat)`, `encodeIndexFileBytes`/`encodeIndexInOrder`/`writeIndexFile` `objectFormat`, `IndexFile.objectFormat`): versions 2 to 4 with 32-byte ids and a SHA-256 trailer (or `index.skipHash`'s null one), and the extensions holding ids: `TREE` (`parseCacheTree(data, rawLength)`), `REUC` (`parseResolveUndo(data, rawLength)`), a split index's `link` and `sharedindex.<64-hex>` (`parseLinkExtension(data, rawLength)`, `readSharedIndex(..., objectFormat)`), `UNTR` (`parseUntrackedCache(data, objectFormat)`, `newUntrackedCache(ident, flags, objectFormat)`, `excludeFileOid(bytes, objectFormat)`, `UntrackedCache.objectFormat`), a sparse index's directories. `FileStagingStore` and `GitStaging` no longer refuse a SHA-256 index: they read and write it in the format of the repository's config.
- **vcs-store-files:** a SHA-256 repository with packs opens; its pack writes, quarantines, gc (cruft packs and `.mtimes` included), repack, prune and alternates work. Still refused with `UnsupportedObjectFormatError`: a multi-pack-index (at open: `assertNoMultiPackIndexInFormat`, which replaces `assertNoPacksInFormat`; `multiPackIndexWrite`/`Expire`/`Repack`; `repack({ writeMidx })`), bitmaps asked for (`repack.writeBitmaps`, `-b`; git's default for a bare `-a` repack is skipped), the commit-graph (gc skips it unless `writeCommitGraph: true` asks, then reports the refusal as `commitGraphError`), reftables and the transports. `refusePackWritesInFormat` is removed.
- **vcs-commands:** `gc`, `fsck` (packs, `.rev`, the index and bitmap checksums in the repository's format), `verify-pack`, `status` (the untracked cache), `add` and `commit -a` work in SHA-256 repositories.
